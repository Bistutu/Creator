# WebCrate regression

Find the WebCrate project root by its `mygo.json` and read `docs/testing.md` for the current commands. Check `docs/ui-style.md` when a change affects layout or motion.

- On the user's Mac, run local builds, native UI tests, and Playwright through `python3 tools/local_check.py --timeout SECONDS -- COMMAND`. Run one check at a time. The entry point checks host load, memory and disk before starting and during the run, limits Go concurrency and stops the test process group on completion, interruption or timeout. Start with the smallest regression and split cross-platform builds into separate checks. Keep Playwright at one local worker.
- DeskPad and Lima checks wait for the one-minute host load to fall below 40% of logical CPU count both before preparing the display or guest and before starting the suite. Each wait is capped at 60 seconds. The second wait uses the existing timeout budget. The supervisor stops and cleans up native checks at 80% of logical CPU count. Both thresholds have a minimum of 1.0. Run `python3 -B -m unittest discover -s tools/tests` to verify both preflights, interruption, guest cleanup on timeout after boot, and process cleanup when the running limit is reached.
- Before launching any native test, check for existing test processes and Lima guests. Keep DeskPad running after every check, including failures and timeouts. Reuse the same virtual display for later runs. Clean up the test windows, processes, and temporary data, then verify cleanup before starting another check. Keep the user's Creator windows and profiles independent of test data.
- Run `go run ./cmd/package -prepare` first when testing generated apps on the current platform. Use `go test -count=1 ./... -coverpkg=./... -coverprofile=coverage.out` to measure Go coverage. The icon fixtures need loopback networking.
- Reproduce UI actions with MyGo's `ui.NewTesterWith` and accessible labels in `desktop_test.go`. Cover the state after actions and failure recovery. Set `WEBCRATE_SCREENSHOTS` to an absolute output directory when visual evidence helps. For changes to motion, assert intermediate frames and repeat with Reduce Motion enabled.
- For combined search terms, run `TestCatalogSearchCombinesTermsWithinTheCategory` and `TestNativeScenarioSearchKeepsChoiceAndExplicitAddresses`. Verify that a matching phrase takes precedence, category and full URLs still work, and canceling restores the original query. Run the recommendation and filtered library launch workflows on DeskPad and Xvfb. The installed Windows preferences test also opens DeepSeek with a combined query in the x64 and ARM64 CI jobs.
- For website link drop, run `TestNativeDroppedWebsite`, `TestMacCreatorReceivesWebsiteLinkOnDeskPad`, and `TestLinuxInstalledCreatorReceivesWebsiteLink`. Start from the library and verify focus, the URL with query and fragment, and the generated application. Use the isolated AppKit pasteboard and Xvfb GTK drag source from the tests.
- On Windows x64 and ARM64, run `TestWindowsWebsiteShortcutIdentity` and `TestWindowsWebsiteProcessIdentity` to read the explicit AppUserModelID from a saved Start menu link and the website process. Exercise the old link upgrade and rename with two apps of the same name. Wine 10.0 stubs the Shell Link property store, so run the property round trip on Windows.
- Use `python3 tools/local_check.py --deskpad --timeout SECONDS -- COMMAND` for local macOS native window tests and visual review. Install with `brew install --cask deskpad` if missing. The entry point reuses the current DeskPad mode or selects a smaller mode, usually 1280×800, when it starts DeskPad as an extended display. When DeskPad is the only online display, keep its current mode. It sets the test display name. Position only isolated test windows. `TestMacInstalledCreatorWorkflow` checks the manager and installed app windows. `TestMacWebsiteWindowInteractions` checks the main and popup windows. Use the DeskPad section in `docs/testing.md` for screenshots and troubleshooting.
